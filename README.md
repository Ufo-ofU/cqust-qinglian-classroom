# 重科青廉课堂

重庆科技大学新生军训期间廉洁教育课堂互动网站。

## 页面
- `/` 学生入口：输入六位课堂码，或扫描教师展示的二维码。
- `/teacher` 教师控制：使用教师口令进入，创建课堂、开放题目、收题、公布结果、切换下一题、结束课堂。
- `/screen?code=六位课堂码` 展示页：供直播和投屏；公布前不展示回答分布或建议答案。

## 课堂规则
内置三个虚构校园情境：班费返款、评选请托、竞赛署名。无姓名、学号或个人排行榜。
匿名参与者使用12小时签名Cookie，同一浏览器每个情境只能保留一份回答；该机制不是实名身份核验，不能防止换浏览器或设备重复参加。
学生约每6至8秒检查课堂状态；公共状态最多缓存2秒，教师状态不缓存。教师开放、收题与公布需给直播传输及网络同步预留时间。
收题检查及投票写入在同一条SQL中完成；重复提交幂等处理。教师控制具有服务端口令验证、签名会话、来源验证和登录尝试限制。

## 数据与配置
使用Sites托管D1保存课堂和回答，迁移文件位于drizzle目录。运行时需要TEACHER_KEY、SESSION_SECRET；只在托管密钥配置及本地忽略文件中保存真实值，禁止提交到源码。
教师口令由活动负责人保管；课堂码可以发给学生。

## 验证范围
已完成桌面和手机界面检查，以及开题、答题、幂等重试、未授权控制拒绝、收题拒绝、结果公布、刷新恢复和下一题流程检查。
本地开发Worker和本地D1测试：4700份模拟回答、50个并行请求，4700份写入成功；100次重复重试后总数仍为4700。此次测试耗时39.788秒，P95为505毫秒。
这不是4700人同时在线的生产压力测试，也不覆盖校园Wi-Fi、手机网络、托管服务配额和实际直播延迟。正式使用前须验证正式托管容量及所有教室的访问情况，分批入场扫码，并保留离线案例讲解预案。

## 运行
使用项目锁定的Node依赖。首次运行执行npm run install:ci，再执行npm run build，按drizzle SQL顺序应用本地迁移。`npm run dev`用于本地联调。
发布由Sites管理，保留.openai/hosting.json中的项目标识和DB绑定。
